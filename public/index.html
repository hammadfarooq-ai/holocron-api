I.Introduction

· · ·

This API keeps a small, mocked record of characters from the nine Skywalker saga films. For each one it gives their allegiances, a short biography, and the films they appear in, grouped into named sections. Every request needs an API key, and every key has a daily request limit set by its plan.

II.Documentation

· · ·

To look up a character, request the URL below with the character's id in the path and your API key in the key parameter.

GET /api/characters/luke-skywalker?key=YOUR_API_KEY

Ids are lowercase names joined by hyphens, such as darth-vader, obi-wan-kenobi or r2-d2. The Archive in section IX lists all of them.

III.The Response

· · ·
id
The id you requested.
name
The character's full name.

Affiliation

True or false for each faction. A character can belong to several.

jedi
Whether the character was trained in the Jedi Order.
sith
Whether the character served the Sith.
republic
Whether the character served the Galactic Republic.
rebellion
Whether the character fought for the Rebel Alliance.
empire
Whether the character served the Galactic Empire.
resistance
Whether the character fought for the Resistance.
first_order
Whether the character served the First Order.

Biography

species
The character's species.
gender
The character's gender, or null for droids.
homeworld
The planet of birth or manufacture, or null if unknown.
birth_year
Year of birth relative to the Battle of Yavin (BBY before, ABY after).
height_cm
Height in centimetres.
mass_kg
Mass in kilograms.

Appearances

movies
The films the character appears in, in episode order. Each gives episode, title, release_year and trilogy.
movie_count
How many films the character appears in.
first_appearance
The earliest film the character appeared in, by release date.
trilogies
The trilogies the character appears in: Prequel, Original or Sequel.

IV.Listing & Filtering

· · ·

Leave out the id to get every character. The response wraps them as { "count": n, "results": [ … ] }, with each result shaped as in section III.

GET /api/characters?key=YOUR_API_KEY

You can narrow the list with any of these parameters, alone or together:

ParameterMeaningExample
nameName contains this text (case-insensitive)name=sky
movieAppears in this episode, 1 to 9movie=4
affiliationBelongs to this faction (see section III)affiliation=jedi

V.Errors

· · ·

Errors are JSON as well, in the form { "error": "…", "message": "…" }.

StatusWhen
400A filter has a value the API doesn't accept, such as movie=12.
401The key parameter is missing or not a known key.
404No character has that id, or no route matches the path. A missing route also echoes the path.
405A method other than GET was used. The Allow header says GET.
429The key has used up its daily limit. Retry-After gives the seconds until the reset.

VI.Rate Limits

· · ·

Each key may make a fixed number of requests per day, depending on its plan (see the table in section II). Every request with a valid key counts, including ones that end in a 400 or 404. The count resets at 00:00:00 UTC every day.

Each API response reports where the key stands:

X-RateLimit-Limit
The key's daily limit.
X-RateLimit-Remaining
How many requests are left today.
X-RateLimit-Reset
When the count resets, as a Unix timestamp in seconds.

The count is kept in memory, so restarting the server resets it.

VII.Access via cURL

· · ·

You can call the API from a terminal or from any programming language.

curl "http://localhost:3000/api/characters/{id}?key={api_key}"
curl "http://localhost:3000/api/characters?movie=4&affiliation=rebellion&key=demo-free-key"

In Windows PowerShell, type curl.exe rather than curl.
